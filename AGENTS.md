# AGENTS.md — maintaining colgrep-mcp

Orientation for the coding agents that maintain this repository. The landing
`README.md` is for humans deciding whether to install; this file is for you.

## What this is

A stdio MCP server (Python, `mcp` SDK v2) that wraps the `colgrep` CLI so
agents get semantic and hybrid code search as tools. The repository root is
at the same time a Claude Code plugin, an Agent Plugins 1.0 plugin and a Codex
plugin; all three launch the same server with `uv run`.

## Gate commands

All Python commands run from `server/`. Green is the norm; a red gate blocks a merge.

```bash
cd server && uv run pytest                      # 190+ tests, ~10 s, no model download
cd server && uv run ruff check                  # lint; no formatter sweep yet
cd server && uv run cz check --rev-range main..HEAD   # every commit on the branch matches CONTRIBUTING
cd server && uv run cz bump --dry-run           # what the next release would be, from history alone
claude plugin validate .                        # manifests
claude --plugin-dir . mcp list                  # the server actually connects under the plugin loader
```

Opt-in: `COLGREP_MCP_REAL=1 uv run pytest` adds the few tests that need the real
`colgrep`; `uv run python tests/e2e/run_e2e.py --corpus <some other repo>` runs the
end-to-end driver (never against this repository, see Traps).

## Conventions

- Commits: `type(scope): description` with a mandatory scope and a WHY body.
  Types and bumps are in `CONTRIBUTING.md` and encoded in `[tool.commitizen]`;
  when the two disagree, fix the disagreement, do not work around it.
- Branches: `main` is always installable; one `task/<leaf>` branch per roadmap
  leaf; rebase onto the target, re-run the gates, merge with `--no-ff`.
- One roadmap step = one commit; the step's `**Commit**` field is the subject.
- Releases: `cd server && uv run cz bump --changelog && uv run pytest`,
  on `main`. This rewrites pyproject, `uv.lock`, the three manifests and `CHANGELOG.md`,
  commits `release(colgrep-mcp): v<x.y.z>` and tags `v<x.y.z>`. Never edit a
  version number by hand.

## Coordinating a campaign

1. Write the architecture report under `__reports__/<topic>/` first; parallel
   implementers code against it.
2. Bootstrap the roadmap with `dirtree-rdm init`, add leaves with `dirtree-rdm add`,
   fill the prose, **commit**, then dispatch.
3. Create each implementer's worktree yourself from the campaign branch
   (`git worktree add <path> -b task/<leaf> <campaign-branch>`) and tell the agent
   the path. Tell it to stop if its leaf file is missing.
4. After a level with more than two parallel branches merges, run a read-only
   reviewer pass and file its findings as an observation report.
5. Close with a knowledge-transfer report; the next campaign starts from its
   Next-cycle Changes.

## Traps

- **Never run the e2e driver or `colgrep init` against this repository or its
  worktrees.** colgrep folds a path into the nearest already-indexed ancestor
  project; the driver refuses this repo on purpose.
- **`colgrep --color never <subcommand>` is a search, not a flag.** Put global
  flags after the subcommand or you will index the cwd.
- **Worktrees see only committed files.** Commit specs before dispatching.
- **After a conflicting merge, grep for `<<<<<<<` before committing.** It has
  bitten this repo twice.
- **`.gitignore` is written for the repo, not just the package**: a bare
  `build/` rule once hid `__roadmap__/**/build/`. Use anchored paths.
- **Do not put an `.mcp.json` at the repo root.** Claude Code reads a root
  `.mcp.json` as *project* MCP config, where `${CLAUDE_PLUGIN_ROOT}` is never
  expanded; that is why the plugin's MCP config lives in
  `.claude-plugin/mcp.json`. What each ecosystem expands where is in
  `__reports__/repo_health/00-findings_launch_placeholders_v0.md`.
- **Manifest and `__init__` versions are derived.** `uv run` re-syncs the
  editable install after a bump, so if a test says they disagree, a file was
  hand-edited; fix the file, not the environment.
