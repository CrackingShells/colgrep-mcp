## Step 1: Module-level handlers on the shared helpers
**Goal**: Make `search`, `find_files`, `expand` importable, greppable symbols that resolve paths, translate errors and annotate themselves the same way `tools_index.py` does.
**Implementation Logic**:
Before editing, dump `Client.list_tools()` to the scratchpad (`uv run python -c` with `Client(build())`, `model_dump_json(indent=2)` per tool, sorted by name) — this is the oracle for the whole leaf. Then: (1) lift the three closures out of `register()` into module-level `async def search(query, paths, …, *, ctx: Context) -> CallToolResult` etc., keeping every `Annotated[..., Field(...)]`, default, docstring and title character-for-character; `register(mcp)` becomes three `mcp.tool(title=..., annotations=READ_ONLY_TOOL)(handler)` lines like `tools_index.register`. (2) Delete `_client_roots`; `_do_search` calls `paths.resolve_target_paths(ctx, paths)`. (3) Replace the `except (ColgrepNotFound, ColgrepFailed, ColgrepTimeout, ColgrepParseError)` block with `async with translate_adapter_errors(path=resolved[0]):`; drop the now-unused imports. (4) `_do_search` returns the `SearchResult` alone — callers use `result.hits`. Re-dump `list_tools()` and `diff` the two files: it must be empty; paste the (empty) diff command and its exit status in the commit body. Tests: `test_tools_search.py` may be edited only where it imports a private name this step renames or removes (`_client_roots`); its assertions do not change.
**Deliverables**: `server/colgrep_mcp/tools_search.py` (module-level `search`, `find_files`, `expand`; `_do_search -> SearchResult`; `register` with three one-line registrations; imports `READ_ONLY_TOOL`, `resolve_target_paths`, `translate_adapter_errors`), `server/tests/test_tools_search.py` (only if a private import had to move)
**Consistency Checks**: `cd server && uv run pytest -q tests/test_tools_search.py tests/test_errors.py tests/test_stdio.py tests/test_smoke.py` (expected: PASS); `cd server && ! grep -nE '_client_roots|except \(ColgrepNotFound|ToolAnnotations\(' colgrep_mcp/tools_search.py` (expected: PASS); `cd server && uv run ruff check` (expected: PASS)

## Step 2: One budgeted renderer
**Goal**: `render_search_text` and `render_files_text` are the same backtracking loop with different header/block/note strings; write the loop once.
**Implementation Logic**:
Add `_render_budgeted(header: str, blocks: list[str], more_note: Callable[[int], str], trailing_notes: list[str], budget: int) -> tuple[str, bool]` holding the existing loop verbatim (append while it fits, backtrack to fit the continuation note, append trailing notes, hard-truncate as last resort, return `(text, capped)`). `render_search_text(result, budget)` becomes: header via `_search_header`, blocks via `[_hit_block(h) for h in result.hits]`, `more_note=lambda n: f"[{n} more hits in structured_content; call expand(hit_ids=[...]) for code]"`, `trailing_notes=result.notes`. `render_files_text` likewise with its own strings and `trailing_notes=[]`. Public signatures unchanged. `tests/test_render.py` must pass **unedited** — if a test fails, the loop was not copied faithfully; fix the helper, never the test.
**Deliverables**: `server/colgrep_mcp/tools_search.py` (`_render_budgeted`; `render_search_text`/`render_files_text` as thin wrappers; `_search_header`, `_files_header`, `_hit_block`, `_file_block` unchanged)
**Consistency Checks**: `cd server && uv run pytest -q tests/test_render.py` (expected: PASS); `git diff --quiet HEAD -- server/tests/test_render.py` (expected: PASS)
**Commit**: `refactor(search): render both text listings through one budgeted loop`

## Step 3: I/O proportional to the output
**Goal**: `find_files` never exposes lines, yet reads every hit file and runs `locate_unit` on up to 300 hits; `expand` returns ≤ `max_lines` lines but reads whole files. Make both do only the work their output needs, and measure it.
**Implementation Logic**:
(1) `_do_search(..., locate: bool)`: when `False`, skip `_fill_file_cache` and pass an empty `file_cache` so `hit_from_raw` falls back to colgrep's reported lines with `location_verified=False`, and do **not** append the `LOCATION_UNVERIFIED` note (it would be an artefact of skipping, and `FileResult` has no notes anyway). `search` passes `True`, `find_files` passes `False`. Grouping in `find_files` keys on `hit.file`, which `_resolve_hit_file` still normalises — unchanged. (2) `expand`: replace `read_text` + `splitlines` with a worker-thread function `_read_span(file, line, end_line) -> list[str]` that opens the file (`errors="replace"`), `itertools.islice`s lines `[line-1, end_line)`, and strips one trailing `\n`/`\r\n` per line exactly as `splitlines()` would; `truncated`, `code` and every error path stay identical (a `start_idx` past EOF yields `[]` as before). (3) Measure, in a scratchpad script (never committed, never against this repo with a real colgrep): for `find_files`, time `_fill_file_cache` + `hit_from_raw` over 300 synthetic raw hits spread over 100 generated files of 5 000 lines each, before vs after (after = the `locate=False` path); for `expand`, time reading lines 10–60 of a generated 200 000-line file, before (`read_text`+`splitlines`) vs after (`_read_span`). Median of 5 runs each. Put both tables in the commit body. Add one test in `test_tools_search.py` asserting `find_files` produces the same `files` list as before for the fixture (it already does — the existing find_files tests are the oracle; add only a test that `_fill_file_cache` is **not** called by `find_files`, e.g. via monkeypatch counter).
**Deliverables**: `server/colgrep_mcp/tools_search.py` (`_do_search(..., locate: bool)`, `_read_span`, `expand` using it), `server/tests/test_tools_search.py` (`test_find_files_does_not_read_hit_files`)
**Consistency Checks**: `cd server && uv run pytest -q tests/test_tools_search.py tests/test_render.py` (expected: PASS); `cd server && uv run ruff check` (expected: PASS)
**Commit**: `perf(search): skip file reads in find_files and read only the requested span in expand`
