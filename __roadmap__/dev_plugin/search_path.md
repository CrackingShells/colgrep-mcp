## Step 1: FileHit-only path for find_files
**Goal**: `find_files` does work proportional to its output (files), not to colgrep's raw hit list.
**Implementation Logic**:
Before touching code, dump the oracles into the scratchpad: `Client.list_tools()` full `model_dump(mode="json")` and `find_files(query="config parsing", limit=10).structured_content["files"]` against `tests/fake_colgrep.py`. Then restructure `_do_search` so the raw-hit conversion is a step the caller chooses: `search` keeps `hit_from_raw` (locate, snippet, `hit_id`); `find_files` folds raw hits straight into `FileHit`s — file key normalised once per hit through the same absolute-path rule `_resolve_hit_file` applies (F13), `best_score` from the first hit per file, `hits` count, `top_units` capped at 5 — with no `SearchHit`, no `hit_id` string, no `locate_unit`. `_read_file_off_loop`/`_fill_file_cache` are not called on this path (the existing `test_find_files_does_not_read_hit_files` stays green). If you touch `hit_from_raw`'s double `resolve()` of `unit.file` (KT-C open question), fold it; otherwise leave it and say so. Micro-benchmark in the scratchpad: 300 raw hits over 100 files, median of 5, old vs new conversion; put the numbers in the commit body. New test: monkeypatch `tools_search.hit_from_raw` with a counter and assert `find_files` never calls it — run it against the old code first and confirm it fails. Re-dump both oracles; `diff` must be empty.
**Deliverables**: `server/colgrep_mcp/tools_search.py` (`_do_search` split so `find_files` uses a `FileHit` fold; `search` unchanged in behaviour), `server/tests/test_tools_search.py` (`test_find_files_never_builds_search_hits` plus the kept `test_find_files_does_not_read_hit_files`)
**Consistency Checks**: `cd server && uv run pytest -q && uv run ruff check && uv run ruff format --check` (expected: PASS)
**Commit**: `perf(search): fold find_files raw hits straight into FileHit without building SearchHits`

## Step 2: One summary notification instead of one per stderr line
**Goal**: A `search` call costs the client at most one `notifications/message` frame, and only when it carries the fact the result cannot (the index was rebuilt).
**Implementation Logic**:
Measure first: a legacy-mode `Client(build(), mode="legacy")` with a logging callback (see `tests/test_tools_index.py::test_doctor_reports_client_root_when_env_root_unset` for the legacy-mode client shape, and the SDK's `Client` `log_handler`/logging callback parameter) counts `notifications/message` frames and sums their `data` bytes for one `search` against the fake, which emits its index-update chatter on stderr (check `tests/fake_colgrep.py` for how many lines; add a knob only if it has none — the fake is owned by no one this cycle, so report rather than edit it if a change is needed and measure with what it emits). Then change `_do_search.on_stderr` to only append to `stderr_lines` (still needed for `index_updated`, R05 D7), and after the adapter call send one `safe_log(ctx, "info", ...)` naming the rebuild only when `index_updated` is true. Measure again; the commit body carries frames and bytes before/after. New test pins "at most one log notification per `search`, and zero when the index was already current"; run it against the old code first and confirm it fails. This is a client-visible delta listed as intentional in R01 §C8. Write `__reports__/dev_plugin/01-findings_stderr_notifications_v0.md` (findings template: front matter, headline result, results table with the before/after frames and bytes, observations, steering questions) and add a Round 01 entry to `__reports__/dev_plugin/README.md`. If the measured saving is zero frames, keep the code change out, write the report with that result, and use the commit type `docs(reports)` for the report alone.
**Deliverables**: `server/colgrep_mcp/tools_search.py` (`_do_search.on_stderr` collects only; one post-call summary via `safe_log`), `server/tests/test_tools_search.py` (`test_search_sends_at_most_one_log_notification`), `__reports__/dev_plugin/01-findings_stderr_notifications_v0.md`, `__reports__/dev_plugin/README.md`
**Consistency Checks**: `cd server && uv run pytest -q && uv run ruff check && uv run ruff format --check && test -f ../__reports__/dev_plugin/01-findings_stderr_notifications_v0.md` (expected: PASS)
**Commit**: `perf(search): send one summary log notification per search instead of one per stderr line`
